How a request flows through the backend

Every request passes through the Edge proxy, which checks session cookies and redirects unauthenticated users. Server components fetch data via Prisma. Server actions handle mutations.

Three roles, three isolated session systems. The superadmin controls exactly which modules each staff member can access via a creation wizard with 18 permissions across 9 modules.

Section 5

Order lifecycle — 13 states, strictly enforced

Orders transition through a strict state machine. Each transition is logged in order_status_history with the user ID and timestamp. Inventory is reserved at checkout and released on cancellation.

1 Creation & Payment

PAYMENT_PENDING→ PENDING→ CONFIRMED

Customer places order → Razorpay/COD selected → payment verified → order confirmed. If payment fails: PAYMENT_FAILED or FAILED.

2 Fulfillment

CONFIRMED→ PACKING→ READY_TO_SHIP→ SHIPPED

Admin fulfills order → packs → creates shipment (AWB generated via Shiprocket/Delhivery) → dispatched.

3 Delivery

SHIPPED→ OUT_FOR_DELIVERY→ DELIVERED

Carrier tracking webhook updates status → customer notified via WhatsApp/SMS → delivered.

4 Termination

CANCELLED→ RETURNED→ REFUNDED

Cancellation restocks inventory. Returns trigger RMA. Refunds processed via Razorpay.
